TA Go connector

The TA client and related trusted execution environment (TEE) adapters encapsulate all the functions needed to collect evidence, package it as a quote, and obtain an attestation token from the TA service. Both attesters and relying parties can use the client modules.

The TA Go client modules, build instructions, and installation instructions are on GitHub at intel/ta-client-for-go. The main branch contains the latest release. The TA Go client code is open source and provides examples of how to use the following API functions.

note

We are transitioning from manually created API documentation (this article) to Go package documentation generated from comments in the codebase. For more information, see the TA Client for Go package documentation on pkg.go.dev. The package documentation is more complete than this article. We will remove the API documentation from this article in a future release.

Go client API index​

go-connector APIs​

Attest
Collects evidence and requests an attestation token from TA for clients that use a Passport validation model.

GetNonce
Retrieves a signed nonce and parses it to JSON.

GetToken
Requests an attestation token from TA. GetToken provides more control than Attest by allowing a confidential app to include user data, provide a nonce, and modify evidence structures before requesting a token. GetToken supports both Passport and Background-check attestation models.

GetTokenSigningCertificates
Retrieves a JSON Web Key Set (JWKS) that contains the collection of signing certificates that TA uses to sign attestation tokens.

VerifyToken
Verifies that a TA attestation token is properly formatted and signed.

go-sgx APIs​

CollectEvidence
Collects evidence from an Intel® SGX enclave and formats it as a quote for attestation.

NewEvidenceAdapter
Instantiates a new Intel SGX Go adapter.

go-tdx APIs​

NewEventLogParser
Reads and parses the ACPI event log that contains TD startup events.

NewEvidenceAdapter
Instantiates a new Intel® TDX evidence collection adapter.

CollectEvidence
Collects evidence from an Intel TDX TD and formats it as a quote for attestation.

Decrypt
Decrypts an encrypted binary object.

GenerateKeyPair
Creates an RSA key pair. The default key length is 3072 bits.

GetEventLogs
Gets the TD event logs that contain the events used to create the RTMR(0-3) hash data.

go-nvgpu APIs​

NewCompositeEvidenceAdapter
Creates a new composite evidence adapter for Intel TDX and GPU evidence.

GetEvidence
Collects evidence from the GPU.

GetEvidenceIdentifier
Returns the evidence identifier, which is currently set to "nvgpu".

GPUAttester
Collects evidence from a remote GPU attester.

GPUEvidence
Returns the GPU evidence collected from the attester.

Go client library structure​

go-connector creates a secure connection to TA and invokes the attestation-related REST APIs. Confidential computing clients and relying parties can use go-connector. The only prerequisites are Go and the correct URLs, API key, and TLS configuration.

go-sgx is required to collect evidence (a quote) from an Intel SGX enclave. go-sgx requires Intel SGX DCAP and an Intel SGX-enabled platform.

go-tdx collects evidence from an Intel TDX trust domain. Two variants are currently available, with more in development:

  • Intel TDX platform adapter: Supports on-premises and cloud platforms that use the Intel TDX stack and PSW. This version of go-tdx is in the main branch of the client repository.
  • Azure confidential VM adapter for Intel TDX: Supports TDs running only on Azure confidential VMs with Intel TDX. This adapter is a fork of the Intel TDX adapter, customized for Azure's implementation of Intel TDX. It requires the TPM2 TSS library but not Intel SGX DCAP. This version of go-tdx is in the azure-tdx-preview branch of the client repository.

go-amd collects measurement data from AMD SEV-SNP hardware platforms during remote attestation and integrates with the existing attestation workflow.

Basic attestation API workflow​

The following steps describe the basic attestation workflow. Many variations are possible. Except for Attest, which requires a TEE adapter, both the attester and the relying party (RP) can use all the APIs.

  1. New: Create a connector for TA SaaS.
  2. NewEvidenceAdapter: An attesting TEE creates a new evidence adapter. (RPs skip this step.)
  3. Intel TDX clients must call NewEventLogParser to get the ACPI tables before creating a new adapter.
  4. Attest: The simplest option for attesters that use the Passport attestation model. It gets a nonce, collects evidence, and requests an attestation token. If successful, it returns the token.
  5. GetNonce: Gets a nonce to include with the quote in the attestation request.
  6. (EvidenceAdapter) CollectEvidence: Collects evidence for a quote. The attester can add TEE or application user data to the evidence collected from the TEE.
  7. GetToken: Requests an attestation token (JWT) from TA after receiving a nonce, evidence collected from the TEE, and optional user data.
  8. VerifyToken: Checks that an attestation token is properly formatted and signed by TA.
  9. GetTokenSigningCertificates: Retrieves a JWKS that contains the signing certificates used to sign nonces and JWTs.

TEE attesters and RPs use the other APIs as needed.

Attest​

Attest provides a relatively simple method to obtain an attestation token for the client.

func (connector *trustAuthorityConnector) Attest(args AttestArgs) (AttestResponse, error)

Parameters​

NameDatatypeDescription
ArgsAttestArgsA type structure that holds the request parameters needed for attestation.
AttestArgs.AdapterEvidenceAdapter
AttestArgs.PolicyIds[]uuid.UUIDAn optional array of up to 10 policy IDs to apply during attestation.
AttestArgs.RequestIdstringAn optional RequestID.
AttestArgs.TokenSigningAlgstringAn optional value that specifies the token signing algorithm. Allowed values are { "PS384" | "RS256" }. The default is PS384.
AttestArgs.PolicyMustMatchboolAn optional value that overrides the default token issuance behavior. If set to true, all supplied policies must match for a token to be issued. If set to false or omitted, an attestation token is issued unless an error occurs. For more information, see Policy results.

Returns​

NameDatatypeDescription
AttestResponsetypeA type structure that contains the JWT and HTTP response headers.
AttestResponse.TokenstringA base64-encoded attestation token (JWT).
AttestResponse.Headershttp.HeaderThe HTTP response headers returned from TA.

Usage​

Attest is designed for the Passport attestation model when the attester wants a token and does not need to append user data to the evidence. The attester needs to create a TA client connection and evidence adapter before calling Attest. To include user data with the evidence, see GetToken.

If you do not provide policy IDs, TA uses the policies (if any) associated with the API key. If you provide a list of policy IDs, the supplied policies replace the associated policies, which are not evaluated.

If you don't provide a request ID, the API gateway generates a random ID that isn't guaranteed to be unique.

The TokenSigningAlg option lets you choose RS256, which is less computationally intensive than PS384 or might be compatible with other systems.

Attest performs the following actions:

  • Gets a nonce from TA.
  • Collects evidence by using the TEE adapter.
  • Forwards the evidence and policy IDs to TA.
  • Returns an attestation token and HTTP response headers.

Example​

req := connector.AttestArgs{
    Adapter:   adapter,
    PolicyIds: policyIds,
    RequestId: reqId,
}
resp, err := connector.Attest(req)
if err != nil {
    return err
}

GetToken​

GetToken requests a new TA attestation token.

func (connector *trustAuthorityConnector) GetToken(args GetTokenArgs) (GetTokenResponse, error)

NameDatatypeDescription
GetTokenArgs.Nonce*VerifierNonce
GetTokenArgs.Evidence*EvidenceAn evidence structure returned from a TEE adapter. Evidence contains the quote for attestation.
GetTokenArgs.PolicyIds[]uuid.UUIDAn optional array of up to 10 policy IDs to apply during attestation.
GetTokenArgs.RequestIdstringAn optional RequestID.
GetTokenArgs.TokenSigningAlgstringAn optional value that specifies the token signing algorithm. Allowed values are { "PS384" | "RS256" }. The default is PS384.
GetTokenArgs.PolicyMustMatchboolAn optional value that overrides the default token issuance behavior. If set to true, all supplied policies must match for a token to be issued. If set to false or omitted, an attestation token is issued unless an error occurs. For more information, see Policy results.

Returns​

NameDatatypeDescription
GetTokenResponsetypeA type structure that contains the JWT and HTTP response headers.
GetTokenResponse.TokenstringA base64-encoded attestation token (JWT).
GetTokenResponse.Headershttp.HeaderThe HTTP response headers returned from TA.

Usage​

Use GetToken for scenarios where Attest does not provide enough flexibility. GetToken allows a confidential app to include user_data, provide a nonce, or modify evidence structures before requesting a token. GetToken supports both Passport and Background-check validation models.

Example​

req := connector.GetTokenArgs{
    Nonce:     nonce,
    Evidence:  evidence,
    PolicyIds: policyIds,
    RequestId: reqId,
    TokenSigningAlg: alg,
    PolicyMustMatch: matchFlag,
}
resp, err := connector.GetToken(req)
if err != nil {
    fmt.Printf("Something bad happened: %s\n\n", err)
    return err
}

go-sgx adapter API reference​

Before you integrate an Intel SGX workload with the TA client, the workload must implement a function to generate an enclave report. This function should take the SHA256 hash of the nonce and user data to form report data for the sgx_create_report API. The TA Attestation Service performs a report data verification in which it expects the report data to be a SHA256 hash of the nonce and user_data.

import "github.com/intel/ta-client-for-go/go-sgx"

The following code fragment creates a new Go SGX adapter and uses it to collect a quote from the SGX TEE.

import "github.com/intel/ta-client-for-go/go-sgx"

adapter, err := sgx.NewEvidenceAdapter(enclaveId, enclaveHeldData, unsafe.Pointer(C.enclave_create_report))
if err != nil {
    return err
}

evidence, err := adapter.CollectEvidence(nonce)
if err != nil {
    return err
}

go-tdx adapter API reference​

The TA Intel TDX Attestation client includes a Go client and a CLI that you can use from the command line or from languages other than Go. Use either tool to add Intel TDX remote attestation to your application.

Two variants of the TA go-tdx adapter are currently available, as described in the next section. Some details of an Intel TDX client implementation for cloud service provider (CSP) platforms differ from the standard Intel TDX TCB that runs on a hosted or on-premises server. CSP platforms require a customized adapter to map their implementations to the requirements of the TA evidence verification service. The TA go-tdx adapters differ mainly in how they combine the evidence collected from the TD with user data, if supplied, and hash it for verification. Nearly all API functions are identical across adapters. Where behavior differs, the API's Usage section describes the difference.

TA go-tdx variants​

  • go-tdx for Intel TDX-enabled platforms. The code for this adapter is in intel/ta-client-for-go/go-tdx on the main branch.
  • go-tdx for Microsoft Azure confidential VMs with Intel TDX. The code for the Azure adapter is in intel/ta-client-for-go/go-tdx on the azure_tdx_preview branch.

The go-tdx adapter for Azure confidential VMs with Intel TDX differs from the standard Intel TDX stack in the following ways:

  • The tdreport.report_data hash doesn't measure user data. It only measures the Azure TD runtime data provided by the Azure "paravisor" component.

  • Azure TD runtime data is always a JSON object literal.

  • If the user data is JSON, it's output as JSON in the attester_user_data claim. If the user data is binary, it's output as base64-encoded data in the attester_held_data claim.

  • TA requires a hash of the runtime data to be present in the TDREPORT.report_data field. The customized go-tdx adapter for Azure TD handles the logic to retrieve the runtime data from the paravisor. The Azure TD runtime data has a predefined JSON data structure, which includes a 64-byte user-data field. The customized go-tdx adapter for Azure TD uses the runtime_data.user-data field to hold the SHA512 hash of the original user-provided data and nonce (if any).

  • The Azure TDX attestation endpoint is api.trusthauthority.com/appraisal/v1/attest/tdxvm. This endpoint accepts a user_data parameter in the request:

    {
      "quote":"<tdx-quote>",
      "runtime_data": "<paravisor runtime data>",
      "policy_ids":[<policy_ids>],
      "verifier_nonce": [<verifier nonce>],
      "user_data": "<user-provided data>"
    }

  • TDREPORT.report_data is used to verify the integrity of runtime data. (This behavior is common to both go-tdx adapters.) A SHA256 hash is calculated from the runtime data and then stored in the lower 32 bytes of the TDREPORT.report_data field.

Example​

The following code fragment creates a new TDX adapter and then collects evidence for a quote. This sample assumes that you previously obtained a nonce for CollectEvidence.

import "github.com/intel/ta-client/go-tdx"

evLogParser := tdx.NewEventLogParser()
adapter, err := tdx.NewEvidenceAdapter(tdHeldData, evLogParser)
if err != nil {
    return err
}

evidence, err := adapter.CollectEvidence(nonce)
if err != nil {
    return err
}

CollectEvidence (Intel TDX)​

CollectEvidence collects a quote from the Intel TDX trust domain. It takes a nonce as input, which is hashed (along with user data, if supplied) during trust domain report creation. The SHA512 hash of the nonce and user data is stored in TDREPORT.report_data, which is output in the attestation token in the tdx_report_data claim. TA requires the report_data hash for quote verification, and custom clients must ensure that the hash is present.

func (adapter *tdxAdapter) CollectEvidence(nonce []byte) (*connector.Evidence, error)

Parameters​

NameI/ODescription
nonceInputA TA nonce.

You can also add user_data to the evidence by including it in the tdxAdapter.uData field.

Returns​

If successful, CollectEvidence returns an Evidence structure; otherwise, it returns an error.

Decrypt​

Decrypt takes encrypted data as input and decrypts the data by using the private key that is passed in the EncryptionMetadata. On success, the Decrypt API returns a byte array that contains the decrypted data. On failure, it returns an error.

func Decrypt(encryptedData []byte, em *EncryptionMetadata) ([]byte, error)

Parameters​

NameI/ODescription
encryptedDataInputAn encrypted binary object.
emInputAn encryption metadata structure that contains three fields:
PrivateKey: An optional byte array that contains the private key to use for decryption.
PrivateKeyLocation: An optional parameter that contains the path to the private key file. You must provide either PrivateKey or PrivateKeyLocation.
HashAlgorithm: A string value ["SHA256" | "SHA384" | "SHA512" | "SM3_256"] that identifies the hash algorithm.

Returns​

The decrypted object as a byte array.

Example​

The following snippet shows how to decrypt an encrypted blob.

em := &tdx.EncryptionMetadata{
    PrivateKeyLocation: privateKeyPath,
    HashAlgorithm:      "SHA256",
}
decryptedData, err := tdx.Decrypt(encryptedData, em)
if err != nil {
    fmt.Printf("Something bad happened: %s\n\n", err)
    return err
}

GetEventLogs​

The GetEventLogs API returns a trust domain event log in the form of JSON. The trust domain event log consists of all the events that are measured to all four RTMRs, in order. You can use the TD event log to verify the integrity of the RTMRs (Real-Time Monitoring and Response) by replaying all the event measurements in order.

func (parser *fileEventLogParser) GetEventLogs() ([]RtmrEventLog, error)

Parameters​

GetEventLogs does not take any input.

Returns​

The TD event log as a JSON object literal.

Example​

The following snippet collects the event log from a TD.

evLogParser := sevsnp.NewEventLogParser()
eventLog, err := evLogParser.GetEventLogs()
if err != nil {
    return err
}
