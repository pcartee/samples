TA can act as a certificate authority to issue attestation keys (AKs) and AK
certificates for physical TPMs. This feature doesn't apply to virtual TPMs
(vTPMs).

You can provision a TPM with an AK certificate issued by TA. TA AK
provisioning does the following:

1. Verifies the TPM Endorsement Key (EK) against a known list of EK
   certificate authorities.
1. Generates a signed AK certificate.
1. Provisions the TPM with the AK certificate.

## Endorsement Key (EK)

Each TPM has a unique endorsement key (EK) pair set by the TPM manufacturer.
Before issuing an AK certificate, TA checks the TPM's authenticity by
verifying the EK certificate against a publicly available list of known TPM
manufacturer certificate authorities (CAs).

## Attestation Key (AK)

A TPM attestation key (AK) is a key pair used during TPM attestation. A trusted
signing authority (in this case, TA) issues an AK certificate that binds the
AK to the TPM. The AK private key signs TPM quotes, which are evidence used
during TPM attestation. When a verifier such as TA receives a TPM quote, it
uses the AK certificate to verify that a trusted CA endorsed the AK. It then
uses the public key in the AK certificate to verify the quote's signature.
This cryptographically proves that the quote was generated by a TPM endorsed
by the CA.

A TPM can have more than one AK provisioned. Each AK is referenced by a unique
handle, so quotes can be generated using AKs endorsed by different CAs. For
example, if the same TPM will be used for attestation by different verifiers
that trust different CAs, each CA can be used to generate a different AK bound
to the TPM with a different handle. TA can verify only AK certificates that it
issued. AK certificates issued by other CAs cannot be used to endorse a quote
for verification by TA.

## TA defaults

A TPM can have one or more AK handles referencing different AKs. To specify
which handle to use with TA, edit the `ak_handle` field in the Go attestation
client CLI configuration file.

If a user-specified AK or EK handle is less than `0x8100000` or greater than
`0x817FFFFF`, the `provision-ak` command returns an error and exits.

TA AK and EK handle defaults are as follows.

- AK handle: `0x81000800`
- EK handle: `0x81000801`

The `provision-ak` command returns an error and exits if the specified AK
handle—or the default handle, if none is specified—already contains an AK. Use
the examples below to delete existing AKs.

:::warning

Deleting existing AK handles is permanent. After an AK handle is deleted, you
cannot restore it.

:::

The following example uses `tpm2-tools` to delete existing handles.

```sh
tpm2_evictcontrol -c 0x81000801
tpm2_evictcontrol -c 0x81000800
```

### AK provisioning command

To start AK provisioning, use the `provision-ak` command.

The command writes AK certificates to standard output (stdout). Redirect the
output or copy the AK certificate as needed. Specify the AK certificate path
in `config.json` as `"file://<path>"`.

The following example shows the `ak_certificate` field in the configuration
file.

```json
{
  "tpm": {
    "ak_certificate": "file:///home/user/akcert.pem"
  }
}
```

Use the following command to collect an AK certificate from TA.

```bash
./ta-cli provision-ak -c ~/config.json
```

Use the following command to collect the AK certificate and save it to a file.
For example, this command saves it to `~/akcert.pem`, which should match the
path specified in `config.json`.

```bash
./ta-cli provision-ak -c ~/config.json > ~/akcert.pem
```

### Generate a TPM quote and request attestation from TA

After specifying the EK and AK handles and configuring `config.json` to point
to the TA-signed AK certificate, use the following command to collect a token
from TA.

```bash
./ta-cli token --tpm --tdx -c ~/config.json
```

### Troubleshoot `provision-ak`

The `provision-ak` command returns an error and exits if it cannot access the
TPM because of a permission or authentication issue, or if an AK already
exists at the user-configured `ak_handle`. The command also returns an error
and exits in the following cases:

- The EK handle already exists at `ek_handle`.
- An AK already exists at `ak_handle`.
- TA returns an error when the command requests an AK certificate, such as a
  network or server error.

During attestation, TA returns an error if the TA AK certificate is expired or
revoked.
